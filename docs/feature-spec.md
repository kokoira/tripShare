# TripShare 機能仕様書

## 概要

本ドキュメントは、旅行記録SNSアプリ「TripShare」の機能仕様を人間が読みやすい形式でまとめたものである。  
X/Twitter のタイムライン形式を参考にしたテキストベースのSNSであり、学習目的で開発する。

## 技術スタック

| レイヤー | 技術 |
|---------|------|
| フロントエンド | Next.js 15 / React 19 / TypeScript 5 / Tailwind CSS 3 |
| バックエンド | Ruby on Rails 7.2（APIモード）/ Ruby 3.3 |
| データベース | MySQL 8.0 |
| 画像保存 | AWS S3 |
| 実行環境 | Docker Compose |
| インフラ（本番想定） | EC2 + RDS + ALB（AWS） |

## 機能一覧

| No. | 機能名 | 概要 |
|-----|--------|------|
| 1 | ユーザー登録 | メールアドレスとパスワードでアカウントを作成する |
| 2 | ログイン・ログアウト | 認証・セッション管理を行う |
| 3 | 旅行記録の投稿 | テキストで旅行の記録を投稿する |
| 4 | タイムライン表示 | 投稿を時系列で一覧表示する |
| 5 | コメント機能 | 投稿に対してコメントを付ける |
| 6 | いいね機能 | 投稿に対していいねを付ける |
| 7 | 画像投稿機能 | 旅行記録に画像を添付する |
| 8 | フォロー・フォロワー機能 | 他のユーザーをフォローする |
| 9 | ユーザー検索機能 | ユーザーを検索しプロフィールを確認する |
| 10 | プロフィール編集機能 | 表示名・自己紹介を編集する |
| 11 | ハッシュタグ機能 | 投稿にタグを付け、タグ別に閲覧する |
| 12 | UI/UX共通要件 | トースト通知・ライトボックス・おすすめユーザー・トレンドタグ |
| 9 | ユーザー検索機能 | ユーザーを検索しプロフィールを確認する |

## X/Twitter との違い

- インプレッション数は表示しない
- リツイート機能はない
- 旅行記録に特化したSNS

## 1. ユーザー登録

### 目的
アプリを利用するためのアカウントを作成する。

### 基本フロー
1. ユーザーが登録画面でメールアドレスとパスワードを入力する
2. 登録ボタンを押す
3. アカウントが作成され、自動的にログイン状態になりホーム画面へ遷移する

### 入力項目

| 項目 | 必須 | バリデーション |
|------|------|--------------|
| メールアドレス | ○ | RFC 5322形式に準拠、重複不可 |
| パスワード | ○ | 8文字以上128文字以下 |

### エラーケース
- メールアドレスの形式が不正 → エラーメッセージ表示
- 既に登録済みのメールアドレス → エラーメッセージ表示
- パスワードが要件を満たさない → エラーメッセージ表示
- 未入力項目がある → エラーメッセージ表示
- システムエラー発生 → エラーメッセージ表示、不完全なデータは残さない

### セキュリティ
- パスワードは不可逆変換（ハッシュ化）して保存する

---

## 2. ログイン・ログアウト

### 目的
自分のアカウントで旅行記録を投稿・閲覧するために認証を行う。

### ログイン フロー
1. ユーザーがメールアドレスとパスワードを入力する
2. ログインボタンを押す
3. 認証成功 → タイムライン画面へ遷移（10秒以内に応答）

### ログアウト フロー
1. ユーザーがログアウトボタンを押す
2. セッションが破棄され、ログイン画面へ遷移する

### セキュリティ対策
- **アカウントロック**: 5分間に10回連続で失敗 → 30分間ログインをブロック
- **セッション有効期限**: 24時間経過でセッション無効化、再ログインを要求
- **入力バリデーション**: メールアドレス形式チェック、パスワード長チェック（8〜72文字）

### アクセス制御
- 未認証状態ではタイムライン画面・投稿画面にアクセスできない（ログイン画面へリダイレクト）

### エラーケース
- 認証情報が不正 → エラーメッセージ表示（メールアドレスは保持）
- 入力形式が不正 → 該当フィールドにエラーメッセージ表示

## 3. 旅行記録の投稿

### 目的
旅行の思い出をテキストで記録し、他のユーザーと共有する。

### 基本フロー
1. ユーザーが投稿画面で本文を入力する
2. 投稿ボタンを押す
3. 投稿が保存され、タイムラインの最上部に即座に表示される

### 制約

| 項目 | 制約 |
|------|------|
| 投稿本文 | 1文字以上280文字以内（空白のみは不可） |
| 付与情報 | 投稿者のユーザー名、投稿日時（年月日 時分） |

### 投稿の削除
- 自分の投稿にのみ削除ボタンが表示される（他人の投稿には表示しない）
- 削除前に確認ダイアログを表示する
- バックエンド側でも投稿者本人のみ削除可能な権限チェックを行う（API防御）

### エラーケース
- 本文が空または空白のみ → エラーメッセージ表示
- 280文字超過 → エラーメッセージ表示

---

## 4. タイムライン表示

### 目的
全ユーザーの旅行記録を時系列で閲覧する。

### 表示内容
各投稿に以下の情報を表示する:
- ユーザー名
- 投稿本文（200文字まで表示、超過分は「...」で省略）
- 投稿日時
  - 24時間以内: 「◯分前」「◯時間前」の相対表記
  - 24時間以降: 「YYYY/MM/DD HH:mm」形式
- コメント数
- いいね数

### ページング
- 初期表示: 最新20件を表示
- 無限スクロール: 末尾到達で次の20件を追加読み込み
- 全件読み込み済み: 「これ以上投稿がありません」を表示

### タイムライン切り替え
- 「全体」: 全ユーザーの投稿を表示（デフォルト）
- 「フォロー中」: フォローしているユーザーの投稿のみ表示

### エラーケース
- 投稿が0件 → 「まだ投稿がありません」表示
- 取得失敗 → エラーメッセージ + 再読み込みボタン（既存表示は保持）

## 5. コメント機能

### 目的
他のユーザーの旅行記録に対して感想や質問を伝える。

### 基本フロー
1. 投稿のコメントアイコンを押す → コメント一覧を表示
2. コメント本文を入力して送信ボタンを押す
3. コメントが保存され、コメント欄の先頭に追加表示される

### 制約

| 項目 | 制約 |
|------|------|
| コメント本文 | 1文字以上200文字以内（空白のみは不可） |
| 表示件数 | 最大50件（新しい順） |
| 付与情報 | コメント投稿者のユーザー名、日時（YYYY/MM/DD HH:mm） |

### コメントの削除
- 自分のコメントのみ削除可能
- 削除前に確認ダイアログを表示する

### エラーケース
- 本文が空または空白のみ → エラーメッセージ表示
- 200文字超過 → エラーメッセージ表示
- 保存失敗 → エラーメッセージ表示（入力内容は保持）
- 削除失敗 → エラーメッセージ表示（コメントは残す）
- コメント0件 → 「コメントがありません」表示

---

## 6. いいね機能

### 目的
共感した旅行記録に好意的な反応を示す。

### 基本フロー
- いいねボタンを押す → いいね追加、ボタンがアクティブ状態（色付き）に変化
- もう一度押す → いいね取消、ボタンが非アクティブ状態に戻る

### 制約
- 1ユーザーにつき1投稿に1回までいいね可能（トグル式）
- いいね数の反映は2秒以内
- いいね数が1000以上の場合は短縮表示（例: 「1K」「10K」）

### エラーケース
- 未認証でいいね → ログインを促す通知表示
- 操作対象の投稿が既に削除されていた場合（レースコンディション）→ 該当投稿をタイムラインから除去

## 7. 画像投稿機能

### 目的
旅先の風景や食べ物を視覚的に記録する。

### 基本フロー
1. 投稿作成時に画像を選択・添付する
2. 投稿と一緒に画像が保存される
3. 投稿詳細画面に添付画像が表示される（複数枚は左→右の順）

### 制約

| 項目 | 制約 |
|------|------|
| 最大添付枚数 | 4枚/投稿 |
| 対応形式 | JPEG, PNG, GIF |
| 最大ファイルサイズ | 5MB/ファイル |
| 最小解像度 | 幅・高さともに10px以上 |
| サムネイル | 短辺200px（アスペクト比維持）にリサイズ |

### 画像保存先
- AWS S3 に保存

### エラーケース
- 5枚以上添付 → エラーメッセージ表示
- 非対応形式 → エラーメッセージ表示
- 5MB超過 → エラーメッセージ表示
- 10px未満 → エラーメッセージ表示
- アップロード失敗 → エラーメッセージ表示（テキストと他の画像は保持）

---

## 8. フォロー・フォロワー機能

### 目的
興味のあるユーザーの投稿を継続的に追跡し、タイムラインをカスタマイズする。

### フォロー操作
- 他ユーザーのプロフィール等でフォローボタンを押す → フォロー関係を保存
- フォロー済みユーザーのフォロー解除ボタンを押す → フォロー関係を削除
- 自分自身はフォローできない
- 反映は2秒以内

### フォロー上限
- 1ユーザーあたり最大5000フォローまで

### プロフィール表示
- 自分・他ユーザーともにフォロー数とフォロワー数を表示

### 一覧表示
- フォロー一覧: フォロー中のユーザーを新しい順に20件ずつ表示（ページネーション対応）
- フォロワー一覧: フォロワーを新しい順に20件ずつ表示（ページネーション対応）

### タイムライン連携
- 「フォロー中」タブ: フォローしているユーザーの投稿のみ表示
- 「全体」タブ: 全ユーザーの投稿を表示
- フォロー中の投稿が0件 → 「フォロー中のユーザーの投稿がありません」表示

### エラーケース
- フォロー保存失敗 → エラーメッセージ表示、ボタン状態を操作前に戻す
- フォロー解除失敗 → エラーメッセージ表示、ボタン状態を操作前に戻す
- 重複フォロー → 「既にフォロー済みです」表示
- フォロー上限到達 → エラーメッセージ表示

## 9. ユーザー検索機能

### 目的
興味のあるユーザーを見つけてプロフィールや投稿を確認する。

### 検索仕様

| 項目 | 仕様 |
|------|------|
| 検索対象 | ユーザー名 |
| 検索方式 | 部分一致（大文字小文字区別なし） |
| 検索文字数 | 1文字以上50文字以内 |
| 表示順 | ユーザー名の昇順 |
| 1ページ表示件数 | 20件（ページネーション対応） |

### 検索結果の表示内容
- ユーザー名
- プロフィール画像

### プロフィール画面
検索結果からユーザーを選択すると、プロフィール画面へ遷移する。

プロフィール画面の表示内容:
- ユーザー名
- 投稿一覧（新しい順に最大20件）
- フォロー数
- フォロワー数

### エラーケース
- 検索文字列が空 → 「検索文字列を入力してください」表示
- 50文字超過 → 「50文字以内で入力してください」表示
- 検索結果0件 → 「該当するユーザーが見つかりませんでした」表示
- 検索失敗 → エラーメッセージ + 再試行ボタン表示

### タグ検索（検索画面のタブ切り替え）
- 検索画面には「ユーザー」「タグ」の2つのタブが存在する
- 「タグ」タブ: ハッシュタグ名で部分一致検索、投稿数の多い順に表示
- タグをクリックすると該当タグの投稿一覧画面へ遷移

## 10. プロフィール編集機能

### 目的
自分の表示名や自己紹介を更新して自分を表現する。

### 基本フロー
1. 自分のプロフィール画面で「プロフィール編集」ボタンを押す
2. 編集モーダルが表示される
3. 表示名・自己紹介を編集して「保存する」を押す
4. プロフィールが更新される

### 制約

| 項目 | 制約 |
|------|------|
| 表示名 | 必須、空欄不可 |
| 自己紹介 | 任意、最大160文字 |
| 表示対象 | 自分のプロフィール画面のみ（他ユーザーには「フォロー」ボタンを表示） |

### エラーケース
- 表示名が空 → エラーメッセージ表示、保存不可

---

## 11. ハッシュタグ機能

### 目的
投稿にタグを付けて、同じテーマの投稿をまとめて閲覧できるようにする。

### 仕様
- 投稿本文中の `#` で始まる連続した文字列をハッシュタグとして自動認識
- ハッシュタグはクリック可能なリンクとして表示（青色）
- クリックするとタグ別投稿一覧画面に遷移

### タグ別投稿一覧画面
- タグ名と投稿件数を表示
- 該当タグを含む投稿を新しい順に一覧表示
- 0件の場合: 「このタグの投稿はまだありません」表示

## 12. UI/UX共通要件

### トースト通知
操作結果のフィードバックを画面下部に一時的に表示する。

| 種類 | 色 | 用途 |
|------|-----|------|
| 成功 | ダーク背景 + ✓ | 投稿完了、フォロー成功、コメント投稿など |
| エラー | 赤背景 + ✕ | バリデーションエラー、操作失敗 |
| 情報 | ダーク背景 + ℹ | ログアウト完了、削除完了など |

- 約3秒後に自動的にフェードアウトで非表示
- 複数の通知は縦に積み重ねて表示

### ライトボックス（画像拡大表示）
- 投稿画像をクリックすると画面全体にオーバーレイ表示で拡大
- 背景クリックまたは Esc キーで閉じる
- 画像はアスペクト比を維持してビューポートに収まるサイズで表示

### おすすめユーザー（右サイドパネル）
- 未フォローのユーザーを最大4名表示
- 各ユーザーにフォローボタンを配置
- デスクトップのみ表示（モバイルでは非表示）

### トレンドタグ（右サイドパネル）
- 投稿数の多いハッシュタグを一覧表示
- クリックでタグ別投稿一覧に遷移
- デスクトップのみ表示（モバイルでは非表示）

### フォロー解除の確認ダイアログ
- フォロー解除ボタンを押した際、確認モーダルを表示
- 「削除する」で解除実行、「キャンセル」で操作キャンセル
